# Spec-Driven Company

Компания, в которой истина живёт в написанных спеках, агенты их исполняют, а статус виден без вопросов кому-либо.

В этом репозитории нет кода. Только спеки: правила, которые каждый ИИ-агент для кода читает первыми, и документы, из которых растёт проект. Всё остальное ставит ваш агент.

Это русская версия. Английские файлы в корне репозитория — источник; эта папка — их зеркало, слово в слово. Промпты ниже скачивают русские файлы, и агент ведёт docs, журнал и отчёты по-русски.

## Установка: вставьте в агента

Откройте своего агента для кода (Codex, Claude Code, Cursor, Copilot, Gemini CLI, любой другой) и вставьте промпт под вашу ситуацию. Не в терминал, а в агента. Каждый промпт заканчивается отчётом: прочитайте его, откройте ссылки и дайте следующую задачу.

Каждый промпт строит одну и ту же раскладку. Вы создаёте одну папку и открываете её в агенте; остальное делает агент:

```text
my-app/          папка проекта: открывайте в агенте именно её
├─ AGENTS.md     указатель: правила лежат в main/
├─ CLAUDE.md     указатель для Claude Code
├─ main/         репозиторий, чистое зеркало main; руками не правится
└─ _wt/          по одному worktree на задачу, назван по ветке; удаляется после слияния
```

Если папка лежит в облачном диске (Dropbox, iCloud, OneDrive), исключите из синхронизации `_wt/` и каждый `node_modules`, либо держите проекты вне диска.

**1. Пустая папка, свой стек.** Ничего не устанавливается. Что строить, вы скажете агенту следующей задачей.

```text
Настрой Spec-Driven Company в этой папке. Это папка проекта: создай в ней main/ и _wt/. Скачай AGENTS.md, CLAUDE.md, CODEX.md, docs/README.md и docs/journal.md из https://raw.githubusercontent.com/eugeneshilow/spec-driven-company/main/lang/ru/ и сохрани их в main/ под теми же путями. В этой папке напиши два файла-указателя: AGENTS.md с текстом «Это папка проекта. Репозиторий — main/; worktree живут в _wt/, по одному на задачу. Сначала прочитай main/AGENTS.md и следуй ему. В main/ ничего не правится руками.» и CLAUDE.md с единственной строкой «@main/AGENTS.md». Прочитай main/AGENTS.md и с этого момента следуй ему. Заполни main/docs/README.md и первую запись, которая уже есть в main/docs/journal.md; в разделе «Стек» в main/AGENTS.md напиши «none yet» во всех трёх строках. Затем сделай git init -b main в main/ и один коммит на main; AGENTS.md разрешает это для первой установки. Это локальная установка: без remote, без pull request, без деплоя. Готово, когда в main/ лежат пять файлов без плейсхолдеров в квадратных скобках (ссылки не считаются), _wt/ существует, два файла-указателя лежат здесь, и git log в main/ показывает один коммит. Отчитайся.
```

Потом скажите, что строить, например: «Сделай Telegram-бота на Python с aiogram. Остановись перед токеном.» Дальше ведут правила: спека раньше кода, проверка перед каждым коммитом, стоп перед ключами.

**2. Существующий проект.** Ваш код, ваши правила и ваш стек остаются. Метод ложится сверху.

```text
Настрой Spec-Driven Company в этом проекте. Эта папка становится папкой проекта: создай подпапку main/ и перенеси в неё всё остальное, что здесь лежит, включая папку .git, чтобы репозиторий с историей теперь жил в main/; рядом создай _wt/. В этой папке напиши два файла-указателя: AGENTS.md с текстом «Это папка проекта. Репозиторий — main/; worktree живут в _wt/, по одному на задачу. Сначала прочитай main/AGENTS.md и следуй ему. В main/ ничего не правится руками.» и CLAUDE.md с единственной строкой «@main/AGENTS.md». Скачай AGENTS.md, CLAUDE.md, CODEX.md, docs/README.md и docs/journal.md из https://raw.githubusercontent.com/eugeneshilow/spec-driven-company/main/lang/ru/. Каждый сохрани в main/ под тем же путём, если такого файла там нет. Если есть — слей: возьми структуру скачанного файла и положи каждое существующее правило, слово в слово, в тот раздел, где ему место; если два правила противоречат друг другу, оставь существующее, убери скачанное и перечисли конфликт в отчёте. Если ветка по умолчанию называется master, сначала переименуй её в main. Заполни раздел «Стек» в main/AGENTS.md из того, что проект уже использует: из чего сделан, команда проверки, команда запуска; если единой команды проверки нет, назови те, что есть. Ничего не устанавливай, скриптов не создавай. Заполни main/docs/README.md и первую запись main/docs/journal.md из того, что в проекте уже есть; где ничего не известно, напиши «none yet», ничего не выдумывай. Делай это в worktree в _wt/, как говорит main/AGENTS.md; изменение затрагивает только правила и docs, поэтому сам слей его в main, удали worktree, а если есть remote — запушь main. Готово, когда в main/AGENTS.md, main/docs/README.md и main/docs/journal.md не осталось плейсхолдеров в квадратных скобках (ссылки не считаются), два файла-указателя лежат здесь, и проект запускается из main/ так же, как раньше. Отчитайся.
```

**3. Пустая папка, готовый стек.** Выберите строку, откройте её промпт под таблицей, скопируйте весь блок, вставьте. Рецепт живёт внутри промпта; версии не зафиксированы: агент ставит то, что актуально в день запуска.

| Стек | Что вы получаете | Где работает |
|---|---|---|
| Next.js · Tailwind · Convex | веб-приложение с базой данных и админкой, где виден статус проекта; стек, на котором работает vibecoding.ru | только на вашей машине |
| Next.js · Tailwind · Convex · GitHub · Vercel | то же приложение, плюс приватный репозиторий, проверка на каждый pull request, адрес в продакшене, который переезжает при каждом слиянии, и база данных в облаке | онлайн; три входа делаете вы: GitHub, Vercel, Convex |

## Что вы получаете

- `AGENTS.md` — правила: где живёт истина, как работать, ответы, которыми человек может пользоваться, git, стек и проверка, зоны риска, решения, структура, продакшен, отчёт, петля. Его раздел «Стек» — единственное место, которое говорит, из чего сделан ваш проект, как его проверить и запустить.
- `CLAUDE.md` — одна строка, которая направляет Claude Code к `AGENTS.md`. Остальные агенты читают `AGENTS.md` напрямую.
- `CODEX.md` — то, что относится только к Codex поверх `AGENTS.md`: ссылки и медиа в Codex Desktop. Правила он никогда не ослабляет.
- `docs/README.md` — одна страница вашего проекта: что это, решения, где что лежит.
- `docs/journal.md` — решения и почему, только добавление, новое сверху. Первая запись уже там: вы приняли метод.
- Два файла-указателя в папке проекта, `AGENTS.md` и `CLAUDE.md`, пишутся промптом, а не скачиваются: они отправляют любого агента, открытого в папке проекта, в `main/`.

## Зачем

Агенты дают одному человеку силу команды. Без системы они плодят хаос и требуют постоянного присмотра. Spec-Driven Company — это система: спека, конвейер, стекло. Концепт по-русски живёт на [vibecoding.ru/sdc](https://vibecoding.ru/sdc). Этот репозиторий — практика.

**Почему здесь нет кода.** У кода есть версии, а версии надо поддерживать. Рецепт словами не протухает, когда протухает библиотека. Ваш агент читает его и берёт то, что актуально в день запуска.

**Почему агент делает всё сам, даже то, что скрипт сделал бы за секунду.** Потому что дефицит — ваше время и внимание, а не токены. Настроить проект руками — двадцать мелких решений и час; вставить промпт — одно решение и десять минут работы агента, при цене токенов, которая только падает. Две вещи держат эту сделку честной: каждый промпт заканчивается критерием готовности, который агент обязан выполнить, и промпты перепрогоняются чистыми агентами после каждой правки рецепта.

**Почему этот установщик не может устареть.** В нём нечему стареть: ни версий, ни флагов, ни lock-файла. Агент берёт сегодняшние стабильные выпуски (LTS там, где он есть, никогда не пре-релиз) и читает сегодняшний `--help` вместо вчерашних ключей. Когда библиотека меняет форму, рецепт по-прежнему говорит, куда прийти, а новый путь агент находит сам.
